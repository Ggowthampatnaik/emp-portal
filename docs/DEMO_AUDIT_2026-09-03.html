1. Verdict

The portal is in good shape. Every page renders for every role with zero console errors and zero failed requests, the four core workflows (two-stage leave, timesheet submit and approve, payroll maker-checker, Finance release) all complete end to end, and row-level scoping holds under cross-user probing. The unit suites pass. What stands between this build and a confident demo is a short list of real bugs, a handful of demo-data embarrassments, and a dashboard that is clickable but shallow.

2. What was tested

Automated suites (as shipped in the repo)

  • Frontend: npm run typecheck, npm run lint, npm run test (34 files, 298 tests) — all pass.
  • Backend: pytest — 628 pass, 11 fail. Every failure is ModuleNotFoundError for zxingcpp (asset barcode tests) or docx (holiday import tests). Both are listed in requirements/base.txt but are not installed in backend/.venv.
  • E2E walkthroughs: manage.py e2e — 15 walkthroughs, 602 of 607 checks pass. The 5 misses: one cap test whose date window lands on a holiday this week (passes when re-run with a clean window, cap is enforced), and four notification checks in e2e_07 whose leave request collides with a request already in the copied demo DB, so nothing is created and nothing is notified. Both are test fragility, not defects.

Hands-on testing (this audit)

  • Browser walk: Playwright drove Chrome through every route and every tab as Employee, Manager, HR, Admin, Finance and Super Admin at 1440×900, then again at 390px mobile. Checked for console errors, failed requests, error text, horizontal overflow and redirects.
  • Workflow script: 67 API checks against a throwaway copy of db.sqlite3 on port 8010, covering leave rules and two-stage approval, timesheet lifecycle and locking, payroll run maker-checker, Finance query and release, and 25 cross-role access probes. The live demo database was not touched.
  • Code review: two reviewers read every backend view, service and serializer, and every frontend feature, shared component and hook, confirming each finding against the code before reporting it.

Workflow checks that did not pass, and why

  • Employee sees the payslip before Finance releases it. Real finding, see bug H4.
  • Re-processing an already processed run returns 200. Intentional: process replaces payslips until the run is approved. Not a bug, but the UI should say “Reprocess” only while the run is still editable (it does).
  • Forgot-password returned 429. The throttle kicked in after the E2E suite. Good security, just note it if you plan to demo forgot-password more than a few times in an hour.

5. Visual audit, page by page

The portal already has a consistent language: Quicksand headings, Inter body, a restrained navy accent with the Trigyan lime for success, cards with soft shadows, and status chips. That consistency is its biggest asset, so nothing below suggests a redesign. The recurring weaknesses are the same three everywhere: most pages are 40–60% empty at 1440×900, the accent palette is a single blue so nothing has a focal point, and the data is thin (no photos, few rows), which is a seed problem more than a design one.

Login

Verdict: strong, keep
  • Animated gradient background, clear wordmark, honest copy. This is the best-looking screen in the product and sets expectations the dashboard then has to meet.
  • The five feature chips (“Leave & holidays”, “Timesheets”…) are static; make them scroll a tiny preview or drop them, static chips that look like buttons invite a click.
  • Add a small “Demo accounts” link (visible only in DEBUG) so you never type an email on stage.

Dashboard — Employee

Verdict: clean but shallow
  • Good: quick actions above the fold, whole-card links, the amber rail only on cards that want attention, the matched noticeboard pair.
  • “34.0 d” and “40.00 h” read as spreadsheet output. Show 34 days / 40 h; keep decimals only for half days.
  • “Leave available” mixes four leave types into one number. Show the split as a stacked bar (CL 4 · EL 18 · SL 12) so the card teaches something.
  • No activity, no team, no announcements. The lower half is two lists that never change between logins. See section 6 for the redesign.
  • Welcome line is plain text; a small avatar + role + “Thursday, 3 September” makes it feel like their page.

Dashboard — HR / Manager / Admin

Verdict: right idea, wrong numbers
  • Three tiers of cards (My work, Waiting on me, Organization) is the correct structure for a role-aware page.
  • HR sees “Timesheets to approve 3” and “Team size 17 · your reporting branch”, both wrong for HR (bug M8). Admin gets no “Waiting on me” although a payroll run is waiting for approval. Finance gets nothing about the two payslips waiting for release.
  • Eleven identical white cards in a grid have no focal point. Give “Waiting on me” a tinted surface or larger numerals, and shrink the Organization row to a single stat strip.
  • “On leave today: 0” links to Reports. It should open the leave report filtered to today, or better, be a “Who’s out this week” list.

Employees — directory and scope

Verdict: good
  • Card grid, search, department and skills filters, cards/table toggle: this page is demo-ready once photos exist. Initials-only avatars in six colours look like placeholders.
  • The “Reports to …” line should be a link that opens that person’s card; it is plain text today.
  • The Super Admin sees only this page. For the top role that reads as an empty product, see section 7 for a Super Admin overview.
  • Employee detail page: comprehensive and well grouped. Experience dates print raw ISO; bank details are fully unmasked to the owner while masked elsewhere, which is intended but worth a “Show” toggle for on-stage safety.

Org chart and Departments

Verdict: fix the clipping, then fine
  • The fifth report under Sneha is cut off (bug M10). With seventeen people it should also default to “Expand all” so the chart looks like an organisation, not five boxes.
  • Cards need the photo, a department colour dot and a click that opens the directory card; today only “N reports” is interactive.
  • Departments is a plain table with 70% empty page below. A small “headcount by department” bar beside it (already drawn on the Reports page) fills the space with information.

Leave — balances, requests, approvals

Verdict: functional, needs a calendar
  • Four balance cards sit three-and-one, leaving a lone card on the second row and the rest of the page empty. Use a 4-column grid or a single row of compact tiles.
  • The used/pending bar colours (navy vs amber) have no legend.
  • The approvals table is right: balance chip beside each request is exactly what a manager wants. Dates wrap in narrow cells; widen or format as “26–27 Aug”.
  • Missing piece: a team calendar view (the API endpoint exists: /leaves/team-calendar/). A month grid showing who is out is the single most persuasive leave screen you can show a client.

HR approvals

Verdict: good pattern, bad data
  • The info banner explains the two-stage rule in one sentence, good.
  • “vmhjn” under the manager’s name, and a request for last week, are what the audience will read. Data fix, not code.
  • “Send Back To Manager” should be “Send back” with the manager’s name in the confirm dialog.

Timesheets — week grid, requests, submissions

Verdict: strong grid
  • The weekly grid is the best-built interaction in the app: weekend cells muted, per-cell note icons, totals row, week stepper.
  • Below the grid the page is empty. Show a “Recent weeks” strip (status chips for the last 6 weeks) and a “Where my hours went” donut by project.
  • Manager Requests tab shows submitted date as “8/24/2026”. Format it.
  • HR Submissions tab is a strong feature (project-based and employee-based views, Notify buttons) but with 0/17 submitted it looks broken. Seed it.

Submissions (HR)

  • Replace the amber “0/4” chips with a small progress bar per project once the data exists; a bar reads at a glance across five rows.
  • “Notify 4” buttons are good. After clicking, show “Reminded 2 min ago” inline so the action has a visible result.

Payslip — mine

Verdict: good
  • Year tabs → month cards → breakdown is a clear drill-down. The net pay in large type at the bottom-right is right.
  • Add a tiny 6-month net-pay sparkline above the month cards; it turns a list into a story.
  • Status chip says “Approved” before Finance has released (bug H4). Once fixed, show “With Finance” / “Released”.

Payroll runs, salary structures, by project

Verdict: good, tidy the action column
  • Status chips are lowercase (“approved”, “paid”) while every other chip in the app is Title case.
  • On the processed row “Approve” + “Send back” wrap onto two lines. Put Send back in an overflow menu.
  • Salary structures: dates are raw ISO; “Current” chip on every row of a list filtered to current structures is noise.
  • Runs from 2025 still awaiting “Mark paid” look like forgotten work.

Finance

Verdict: good
  • Clear banner, Release/Query pair, expandable rows. Once H4 is fixed this is a complete story.
  • Empty state says “Nothing waiting on Finance” for every filter, including “Released”. Vary the copy.
  • Give Finance a dashboard card (“2 payslips to release · ₹1,46,272”).

Reports

Verdict: adequate, could be the showpiece
  • Charts are small and the two on the Leave tab say the same thing twice (approved vs pending as donut and as bars). Replace the donut with leave taken per month (a line) and keep the bars.
  • Date inputs render as the browser’s “mm/dd/yyyy” while the app is en-IN elsewhere. Use the MUI date picker already in the bundle.
  • Headcount chart legend shows “On notice” and “Inactive” with zero rows; hide empty series.
  • Add a fourth chart per tab, and a “Last 90 days” default range so the charts are never empty on open.

Notifications

Verdict: works, feels like a log
  • Rows are not clickable even though every notification carries a link. Make the row navigate and mark itself read.
  • Add a type icon (leave / timesheet / payslip) and group by day rather than repeating the timestamp on every row.
  • The bell dropdown should show the last five with “View all”, rather than sending people to this page.

Super Admin

Verdict: too empty for the top role
  • The sidebar is one item and the landing page is the same directory an employee sees, plus inline role dropdowns. A client will ask “that’s it?”.
  • Give Super Admin an Overview page: headcount, open approvals across the company, payroll status this month, audit highlights, and a “Sign in as role” explainer of what each role sees. It costs one page and reframes the role as oversight.

Mobile (390px)

Verdict: better than the handbook admits
  • Nothing overflows the page, the drawer works, cards stack, the login is excellent.
  • Tabs are cut off (“Manager a…”) with no scroll hint; set variant="scrollable" with scroll buttons on every tab strip.
  • The timesheet grid shows one day at a time with no indication it scrolls. On phones switch to a day-per-row layout or add a “Mon · Tue · Wed” day switcher.
  • The payslip month cards also scroll off-screen invisibly (“3 payslips” but two visible).

Cross-cutting polish (one afternoon)

  • Fill the empty half. Every list page ends at a table; nothing below. Add a right-hand or bottom “insight” panel per module: leave calendar, hours donut, department bars, run totals trend.
  • Second accent. Introduce the Trigyan lime as a deliberate second colour for “done / released / approved” and a warm amber for “waiting”. Today the lime only appears in role chips.
  • Numbers. Drop trailing “.0”; use tabular figures in tables; ₹ amounts with Indian grouping (₹9,60,602) via Intl.NumberFormat('en-IN').
  • Empty states. Every empty state should say what to do next and offer the button (“No holidays in June · Add holiday”).
  • Dark mode. The toggle exists and the tokens are mode-aware; walk the ten main pages once in dark before Monday, especially chart colours and the login backdrop.
  • Global search. A Ctrl+K palette over people, projects and pages is a small build (the search endpoint exists) and it is the feature clients remember.

9. Demo script

Twenty minutes, six sign-ins, one story: Asha applies for leave and books her week, her manager and HR act on it, payroll runs, Finance releases, and Asha sees her payslip. Steps avoid every known trap above.

  1. Login page (30 s). Point at the background and the forgot-password link. Sign in as asha.rao.
  2. Employee dashboard (2 min). Quick actions, cards, birthdays (click a person to show the directory card), holidays.
  3. Apply for leave for two days next week, CC a colleague. Show the balance card update and the “pending” timeline.
  4. Timesheet: fill this week, add a task note, submit. Then Profile: photo, skills, documents, bank details masked.
  5. Sign in as vikram.nair (manager). Dashboard shows “Leave to approve 1, Timesheets to approve 1”. Approve both from the queues. Open Reports → Timesheet hours for his branch.
  6. Sign in as priya.menon (HR). HR approvals: approve Asha’s request (explain stage two and “send back”). Submissions tab: Notify the outstanding people. Employees: Add employee, show the onboarding gate briefly. Holidays: add one.
  7. Payroll as HR: Open September, Process, expand a run, Send to Finance for Asha.
  8. Sign in as rahul.iyer (admin). Approve the run (maker-checker line). Administration → Users, Audit log (filter to “approve”, once M1 is fixed).
  9. Sign in as fatima.sheikh (Finance). Release Asha’s payslip; raise a query on another to show the loop.
  10. Back as Asha: notification “Payslip released”, open it, Download PDF. End on the mobile view of the dashboard.

Skip in the demo until fixed: deleting a seeded user (H6), Import from Word (H7), removing a profile photo (M2), creating two projects in a row (M5), and anything as Super Admin unless the overview page is built.
